# 数据库迁移

PostgreSQL 18 使用 SQLAlchemy 和 Alembic。业务表由迁移 Job 管理，不在 API 请求或多个服务副本启动时自动建表。

- `0001`：资源、不可变修订、持久操作/任务/执行、凭据、事件与报告。
- `42357d1ae6b2`：执行尝试谱系及实际实时输入。
- `a2d91c50b7e4`：为旧测试集追加仅输入的新修订；保留旧版本及已记录的任务、执行、评分、报告，不覆盖证据。

平台升级时先执行新镜像的 `alembic -c /app/alembic.ini upgrade head`，迁移成功后启动后端。维护窗口需确认没有正在执行或提交的任务；保留数据库、PVC 和加密密钥。新部署由独立 Kubernetes Job 完成，已有环境也使用单次迁移 Job。

输入组迁移的数据修订不在 downgrade 时反向覆盖；历史版本仍可查询。旧包含输出/标准答案的修订只供历史查看，新任务与导出要求当前版本。对应验证见 `server/tests/test_input_only_datasets.py` 和第 23 篇实施记录。
