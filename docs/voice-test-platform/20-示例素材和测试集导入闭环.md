# 示例素材、测试集和本地工作区

日期：2026-10-12。新增功能沿用 Kubernetes Pod-only、不可变版本和显式提交边界，后端仍为单体服务。

## 完整示例与文件交换

`examples/repository-helpdesk` 提供 5 个模块 ZIP、4 个 workflow JSON、1 个包含 3 份素材的 ZIP 和 4 个测试集 JSON。文字、合成音频和印有问题的图片均为固定实际文件，不使用麦克风。测试集的输入绑定素材固定修订；素材转写参考与最终案例参考独立，案例参考默认留空。

正式素材池保留逐文件上传，增加“导入素材包”“导出素材包”，提供校验预览、创建/复用结果、选择和下载。正式测试集增加 JSON 导入、依赖预览、固定素材候选、导出测试集及导出配套素材。配套素材由案例的 ID/版本选取，包括旧修订及已隐藏历史素材；不切换到最新标注。

JSON 导入草稿及幂等 key 可跨关闭、页面导航、刷新和重新登录恢复。ZIP File 在当前素材池页面关闭/重开时保留；离开页面或刷新需要重选，摘要去重防止创建重复修订。提交期间禁用重复提交、输入和关闭；成功后清除 JSON 草稿。提交成功但响应丢失时，重试仍得到同一个测试集。

契约见 [data v1](../../contracts/data/README.md)，下载、界面步骤和安装命令见 [示例 README](../../examples/repository-helpdesk/README.md)。源码构建脚本同时产生全部下载文件；下载工具在同一个 immutable GitHub artifact commit 下检查各文件 SHA-256。

## 事务可见性修正

实测发现默认 request-scope yield 依赖在成功响应之后提交，登录后立即读取会话可能偶发 401。所有管理接口和模块资源接口统一使用 function-scope 数据库依赖，在成功响应发送前提交；提交错误返回 503。没有改变持久队列、单进程调度和模块协议。ASGI 测试显式延迟提交验证响应顺序，并验证提交异常不能发送成功或登录 Cookie。

正常工作区使用 `testflow-dev`，本地入口 `http://127.0.0.1:18765/`，Docker Desktop Kubernetes，独立后端、前端和 PostgreSQL 18。`install.py` 通过正式 API 导入，读取私密访问文件，验证本地 namespace/URL，不输出密码或凭据正文。重复运行按资源内容与幂等 key 复用相同资源和任务。

业务代码仍来自 GitHub 的固定 commit `7c89f3076ab637a3467fbf3d56f2ae7fc8f09e2e`。适配层从 `/workspace/repository` 只读挂载导入函数，Trace 记录实际代码路径和摘要。镜像仍须显式构建并加载；ZIP 不替用户编译后端代码。

## 验收范围

`tests/kubernetes/data_transfer.py` 在一次性工作区验证完整下载、缺依赖预览、摘要错误原子拒绝、重复导入、旧修订、隐藏后的历史媒体、4 个真实 Pod 流程、重复安装、可移植导出和运行实例回收。`tests/kubernetes/transaction_and_media.py` 验证立即读取，以及容器内真实 FFmpeg、原始音频、Range 和隐藏后读取。

`tests/data-transfer-ui.e2e.mjs` 验证正式控件、JSON/ZIP 选择、预览失败、关闭、草稿恢复、提交保护、响应丢失重试、下载和旧素材的配套导出，并检查 1200/1440/1920、中文/英文、浅色/深色布局。布局截图检查不等于全站 0.5% 像素一致性复验，早期原型的模拟导入也不替代新 API 验收。

真实麦克风采集继续按用户要求保留未验收。该示例验证极小 RAG/ASR/OCR/TTS 与真实 Kimi 的闭环，不验收通用语音、图像语义或模型质量。
