# 能力运行配置与节点业务参数

2026-10-12，按最新画布反馈明确配置归属，并补齐模块运行配置持久化。

| 位置 | 配置内容 |
| --- | --- |
| 能力模块 | ZIP 初始声明的镜像、服务端口、固定仓库及只读挂载目录、CPU/内存和实例复用；编辑后保存新平台修订，再验证实际 Pod。 |
| 流程节点侧栏 | 节点名称、描述，以及 ZIP 的参数 Schema 与动态组件定义的业务参数。模块不定义参数时显示空状态。 |
| 流程设置 | 准备/收尾期限、各节点运行超时、固定能力修订。取消不改变画布草稿，保存后进入流程版本。 |
| 画布 | 输入/输出契约、连线、节点删除。开始/结束节点仍保留必要的契约编辑。 |

运行默认值保存到模块数据 `runtime`，通过 `PUT /api/v1/modules/{id}/runtime` 携带 `expected_version` 更新。保存验证固定 commit、凭据类别、Pod 字段及包声明的顺序/独立实例要求，不能降低模块要求。新修订保持原 ZIP、参数 Schema、manifest、组件及包摘要；重复导入同一 ZIP 不覆盖已保存默认值。保存失败保留草稿，409 需要查看最新版本后明确继续。

新节点及切换能力版本时复制已保存默认值和包参数默认值。已有流程节点和任务快照不跟随模块默认值改变。能力参数继续由前端和后端按 Schema 校验，不把平台启动字段混入业务参数，也不按模块名称推断其配置项。

组件加载后，Schema 明确声明的顶层字符串业务凭据字段（`x-testflow-credential`）可通过“配置能力凭据”选择或创建加密凭据，选用 ID 同步回组件参数。它使用 `module` 凭据类型，和 Pod 的 registry 凭据分开；不需要用户手写 ID，也不重新引入全局凭据管理。组件加载或渲染失败时保持错误及只读已保存参数。

连线鼠标悬停或键盘聚焦时显示删除按钮；点击路径不会弹窗，点击按钮后确认删除，取消保留连线。节点删除按钮放在节点卡片上，点击删除形成可恢复草稿并移除关联边；固定开始节点没有删除按钮。侧栏不再提供删除或断开连线控件。

受控画布在选择、删除/恢复和新增节点时保留 React Flow 的尺寸测量结果，新增节点全部测量完成后再适配视野。测量状态只保存在画布组件，不写入业务图或 workflow 文档，避免组件重渲染丢失测量后使节点持续隐藏。浏览器验收在恢复草稿后新增能力节点，检查四个节点均可见并继续实际业务凭据配置。

节点 `description` 随图保存、冻结，并在 `testflow.workflow.v1` 导入导出中保留。当前有 88 个原型具名控件：退休 `disconnect-node`，新增 `edit-module-runtime`、`save-module-runtime`。原控件的历史验收记录继续保留。
