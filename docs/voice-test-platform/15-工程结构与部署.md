# 工程结构与部署

2026-10-11 按用户要求初始化前后端基础结构，部署目标为 Kubernetes，后端暂定单体。根 README 是实际启动和验证入口；本文件描述已落地边界，不把目标功能作为完成状态。

## 平台服务

平台后端采用 Python 3.13 + FastAPI，业务按域拆包、统一应用启动。HTTP API 与未来任务调度、DAG 执行、模块启动、Trace 接收及评分逻辑在同一个服务内组织；当前不拆独立 Worker，也不引入 Redis/Celery 或服务间消息总线。

单体不等于把全部代码放一个文件。features 的 router / schemas / service / models / repository 按职责逐步实现；execution 管执行状态、调度、runners 和 transport；infrastructure 管数据库与文件存储；core 管配置。只为已实现能力添加代码，预留域目前只有包边界。

平台运行环境和模块运行环境独立。Python 仅用于平台自身，模块可以使用任意后端语言。本地进程或 Docker 启动继续遵循模块声明；模块内部是否访问外部 HTTP/私有 WebSocket、加载仓库代码，由模块代码决定。Kubernetes 是平台部署方案，不新增模块能力来源分类或业务表单。

## 前端

正式前端已创建 web 工作区，保持用户指定主版本。当前锁定 React 19.3.0、TypeScript 7.0.2、Vite 8.3.4、HeroUI 3.2.6、Tailwind 4.3.3、React Router 7.18.4、TanStack Query 5.104.1、Zustand 5.0.15；实际完整依赖以 pnpm-lock.yaml 为准。HeroUI 3 使用自身 CSS 和组件，无需旧版 Provider。

app 注册路由，layouts 承载一致导航，features 按业务域放页面与数据接口，shared 提供 API、偏好及公共组件。中文/英文按域放 i18n，通过 index.ts 统一注册；默认中文，语言和主题持久化。styles 统一 Tokens、浅色/深色及 .testflow-* 类名，验收范围为桌面 Web。

当前首页请求真实 /api/v1/system/status，支持手动刷新、连接失败反馈和重试。八个业务入口有对应路由与准备中说明，404 可返回首页。admin 登录、业务表格/表单、DAG 画布和动态配置组件加载后续实现；单文件 demo 保留作交互参考。

packages/module-ui-sdk 只提供配置组件初始 TypeScript 类型，尚无打包或动态加载器。contracts/module 记录待锁定的 HTTP/WS 与运行契约，不提前制造正式协议。画布依赖暂未增加。

## 后端和数据

当前实现系统状态、存活和就绪接口。启动时准备独立数据根目录，包含 assets、module-packages、repositories、runs。数据不写入源代码目录；本地默认 .data，容器 /data。

SQLAlchemy async 与 Alembic 已预留，业务表和迁移尚未生成。PostgreSQL 暂可不配置；设置 TESTFLOW_DATABASE_URL 后，就绪接口检查真实数据库连接。系统状态的 database=configured 仅表示配置存在，不表示迁移或业务持久化完成。数据库连接异常或目录不可写时就绪返回 503，存活仍可正常。

单体初期一个 Pod、一个 Uvicorn 进程。未来支持用户配置的案例并发在同一执行器内完成，不依赖 API 多进程。进程重启恢复、持久执行状态与租约须随执行器实施完成，不能把内存后台任务当作可恢复任务系统。

## Kubernetes

base 部署一个前端、一个后端及 Service、ConfigMap、RWO PVC。development 与 production overlays 分别使用 testflow-dev / testflow namespace 和不同镜像标签、环境配置；production 目前仅为环境模板，不意味着业务已满足上线条件。

后端 Recreate 更新策略避免单副本 RWO 卷的滚动挂载冲突。两个容器非 root、无提权、根文件系统只读；/tmp 是临时卷，/data 是持久卷。已配置数据库通过 Secret 注入。Nginx 静态托管并同源代理 /api，保留 WS 升级转发能力，但当前没有实际流式路由。

平台镜像构建、加载/推送、kubectl apply 与 port-forward 见 deploy/k8s/README.md。需要节点可拉取的镜像及可用 StorageClass。Ingress 仅提供单独示例，由实际集群的入口类、域名与 TLS 配置决定。当前不创建独立数据库、Worker 或模块执行容器资源。

Pod 中启动本地模块，以及运行 Docker 模块所需的执行环境、隔离、网络、卷和清理，将在执行器契约中明确；当前部署不挂载宿主机 Docker Socket、不宣称已支持模块启动。先保持业务契约与平台部署细节分开。

## 基础验收

类型与生产构建、健康/API 测试、浏览器真实连接/刷新/导航/双语/主题/404/断线恢复、镜像构建及只读容器代理通过。原型原有 17 项逻辑测试继续通过。Kustomize 两套 overlay 和 Ingress 示例严格 Schema 校验通过；本机现有集群连接超时，因此没有实际 rollout 或 PVC 供应验证。

浏览器验收使用同一套 foundation.e2e.mjs，通过 CUA Playwright facade 实际执行；常规 Playwright runner 的入口与配置也已创建，命令执行方式见根 README。真实模块 ZIP、仓库同步、私有协议、远端取消、AI 评测与数据库持久化仍需后续业务联调验收。
