# 工程结构与 Kubernetes 部署

平台后端使用 Python 3.13 + FastAPI 单体，数据库 PostgreSQL 18 + SQLAlchemy async + Alembic，部署一个后端 Pod 和一个 Uvicorn 进程。前端使用 React 19/TypeScript 7/Vite 8/HeroUI 3/Tailwind 4，画布使用 @xyflow/react 12.12.0。

```text
web/src/             app、layouts、features、shared、i18n、styles
server/src/testflow/ core、infrastructure、features、execution
server/migrations/   Alembic 环境和不可变迁移
contracts/module/    ZIP、HTTP/WS 与配置组件契约
packages/module-ui-sdk/ 宿主桥接与组件类型
examples/modules/    Python 音频、Node 文本、Go 图片和测试夹具
scripts/             包构建、OpenAPI、部署及验收工具
deploy/k8s/          base、环境 overlays、PVC、Secret、RBAC、迁移 Job
tests/               原型、接口、浏览器和部署验收
```

路由处理 HTTP，领域服务处理规则，仓储管理数据库事务，执行层调度 DAG 和 Pod。资源身份可以更新与隐藏，内容通过不可变 revision 保存；任务创建时冻结全部计划项。异步操作先写数据库再领取，重启不自动重跑不可恢复的活动执行。

生产必须配置数据库 URL、admin 密码摘要及凭据加密密钥，admin 使用 HttpOnly Cookie。Git、镜像与评测凭据保存在加密凭据库，快照和日志只有引用。持久数据使用 `/data` PVC，临时文件使用独立 tmp。

本地开发初始化和 Kubernetes 部署脚本的初始登录统一固定为 `admin / 123456`；每次初始化生成 Argon2 密码哈希，Kubernetes 数据库密码与各环境的凭据加密密钥仍随机生成。已有配置不会被初始化脚本覆盖，备份恢复继续保留源安装的登录和加密配置。

前端、后端、PostgreSQL 及模块均在 Kubernetes。后端 ServiceAccount 只获得当前 namespace 必要 Pod 权限，模块使用独立身份。代码 commit 只读挂载，RWO 模块与后端在同一节点。镜像直接 ENTRYPOINT/CMD 启动，没有本地启动或语言/入口字段。

本地部署和完整验收使用 Docker Desktop 内置 Kubernetes（`docker-desktop` 上下文，kind 单节点），验收使用独立 testflow-e2e namespace；证据保存后回收本次资源。部署、备份、恢复和测试共用显式集群连接，业务后端继续只依赖 Kubernetes API，架构边界不变。开发 Docker 验证不替代 Kubernetes 和真实 AI 联调。操作步骤见 [Kubernetes 部署说明](../../deploy/k8s/README.md)，实现状态和未通过关卡见 [实施记录](16-完整实施记录.md)。

版本发布的 GitHub Actions 使用独立 Linux AMD64/ARM64 runner，构建当前标签或维护者明确选择的 PR commit 的候选镜像，并创建 `testflow-ci-<run-id>-<attempt>` kind 集群。镜像加载仅允许 `docker-desktop` 或显式的 `kind-testflow-ci-` 上下文，同时校验 Kubernetes providerID 与 Docker 节点的集群归属标签；不修改全局 kubeconfig。测试安装、备份恢复和浏览器沿用临时 namespace 及现有脚本，结束回收 namespace、卷和整个测试集群。此扩展只改变测试运行环境，后端单体和 Pod-only 业务边界保持不变。普通 PR 执行范围对应的快速检查，版本标签自动全量；维护者可指定已有标签重跑，或明确添加 `ci:full-tests` PR 标签验证候选版本，见 [Actions 策略](../development.md#github-actions)。

## 用户部署入口

用户使用 [静态部署目录](../../deploy/k8s/beta)，执行一次 `kubectl apply -f deploy/k8s/beta` 创建全部资源。用户 namespace 固定为 `testflow`，后续版本继续使用同一 namespace，通过镜像标签区分 Beta 和正式版本。目录当前引用已发布的 Docker Hub `v0.0.1-beta` 镜像；资源、初始化和依赖等待均由 Kubernetes 控制器管理。操作步骤见 [用户部署](../../deploy/k8s/README.md#用户部署-v001-beta)。

初始化 Job 使用独立 namespace ServiceAccount，只有读取指定两个 Secret 与创建 Secret 的权限，没有更新、删除、列举 Secret 或集群权限。数据库密码、admin 密码哈希、凭据加密密钥在集群中生成，缺失配置恢复和并发创建均读取已持久化的值，禁止静默覆盖不一致的已有配置。

迁移 Job 等数据库可连接；后端等 Alembic 版本与镜像匹配后才启动调度器，前端等后端健康就绪。依赖通过 initContainer 表达，不依赖文件顺序或用户分别等待各资源。初始化和迁移 Job 按镜像版本命名，新版本可以创建新 Job，已有密钥继续保留。

`base` 继续作为平台资源事实来源。维护工具 `scripts/export-kubernetes.py` 合并公开版本镜像、初始化代码、共享安装辅助模块与依赖门禁，导出可直接 apply 的 YAML；`--check` 校验目录与定义同步。初始化脚本及其辅助模块通过同一个 ConfigMap 挂载，使用当前清单的 namespace 校验和密钥生成逻辑，可直接配合已有公开镜像。用户无需运行该维护工具。旧的 Python 研发部署和镜像内清单生成工具作为研发/兼容入口保留，默认入口已改为静态目录。

此调整改变安装初始化的执行位置，新增独立初始化身份及窄范围 Secret 权限；后端单体、Pod-only 模块、持久化与运行权限边界保持原设计。集群内的 `testflow-secrets` 与 `testflow-postgres-secret` 需随数据备份保留，反复 apply 不重置它们。发布镜像 digest 沿用下述首次发布记录，安装简化通过部署清单实现。
